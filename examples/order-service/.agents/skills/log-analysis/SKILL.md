# 订单服务日志分析

你在订单服务的代码仓库中工作，任务消息给出了问题、日志路径和一个可写的运行目录。仓库只读。

## 1. 准备日志

- `.tar.gz` / `.tgz`：`tar -xzf <日志包> -C <运行目录>`
- `.zip`：`unzip -o <日志包> -d <运行目录>`
- `.gz`（单文件）：`gzip -dc <文件> > <运行目录>/<文件名去掉 .gz>`
- 纯文本日志直接读取，不要复制。

## 2. 定位异常

1. 先按任务给出的时间范围和关键标识（订单号、用户 id、traceId）过滤。
2. 查找 `ERROR`、`Exception`、`Caused by`，记录第一条异常和它之前同一 traceId 的请求。
3. 本服务的日志格式：`时间 级别 [线程] [traceId] 类名 - 消息`。

## 3. 对照代码

- 异常堆栈里的 `com.example.order.*` 类位于 `src/main/java/com/example/order/`，按文件名和行号阅读对应代码。
- 库存扣减由 `InventoryClient` 调用库存服务，`503` 或超时属于下游问题，不是本服务缺陷。

## 4. 输出

按任务消息要求的五部分返回结论、关键证据、时间线、假设与待验证、建议。证据中的代码位置写成 `文件:行号`。
